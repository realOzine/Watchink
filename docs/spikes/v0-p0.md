## S-01 / S-04 桌面外壳

- 构建命令（取自 Wails v2.16.0 源码）：

  ```text
  CGO_ENABLED=1 CGO_CFLAGS="-mmacosx-version-min=13.0" \
  CGO_LDFLAGS="-framework UniformTypeIdentifiers -mmacosx-version-min=13.0" \
  go build -tags desktop,production -trimpath -ldflags "-w -s" ./cmd/watchink
  ```

- 最低系统版本定为 macOS 13：Go 1.27 的目标是 macOS 13，更低会有链接警告。
- 用 `cmd/_desktopsmoke` 在真实 WKWebView 里跑的自检全部通过：
  - 页面来源是 `wails://wails`，`isSecureContext` 为 true。
  - 带 `Authorization` 的跨源 GET / POST 成功，预检正常，401 响应体可读。
  - 流式事件不被缓冲：间隔 300 ms 发出的 5 个事件按时到达。
  - `window.go.desktop.App` 暴露的正好是 6 个绑定方法。
  - 30 s AAC 音频经 Range 加载并跳转到 24 s。
- 去掉 Info.plist 里的 `NSAllowsLocalNetworking` 后结果相同；该键作为旧系统的保险保留。
- 正式 `Watchink.app`（27 MB，ad-hoc 签名）启动后会拉起 Engine，WebKit 网络进程与 Engine 建立了 3 条连接。
- 没有验证的部分：窗口渲染、原生打开和保存对话框、Finder 定位、从 Finder 双击启动、下载后的 Gatekeeper 行为。

## S-05 播放

用 Playwright 驱动 Chromium，访问真实 Engine 上一个 640×360、1 分 59 秒的 H.264 / AAC MP4：

- 视频加载到 `readyState = 4`，时长 119.67 s。
- 点击笔记里 `00:28` 的引用，播放器定位到该片段并开始播放。
- 直接设置 `currentTime = 100` 后正常继续播放。
- 打开 `/videos/<id>?t=36460`，`currentTime` 为 36.46 s。

## S-06 whisper.cpp

- 只用 Command Line Tools 就能构建 Metal 版本（`GGML_METAL_EMBED_LIBRARY=ON`，不需要 `metal` 编译器）。`otool -L` 只有系统库和框架。
- 内嵌、释放、执行通过；Gatekeeper 开启状态下没有被拦截，释放和下载的文件都没有隔离属性。
- 首次运行会花约 4.8 s 编译 Metal 库，之后有缓存。
- 实时率（256.3 s 普通话，`say` 合成语音，`-t 8`，含模型加载，各跑一次）：

  | 模型 | VAD | 耗时 | 倍速 |
  | --- | --- | --- | --- |
  | small-q5_1 | 关 | 9.96 s | 25.7× |
  | small-q5_1 | 开 | 9.01 s | 28.5× |
  | large-v3-turbo-q5_0 | 关 | 14.30 s | 17.9× |
  | large-v3-turbo-q5_0 | 开 | 13.92 s | 18.4× |

- **VAD 时间映射不正确。** 静音之后的第一个片段被报在静音开头：实际 138.28 s 恢复的语音被报为 118.06 s（large）和 118.17 s（small），早了约 20 s。VAD 还会丢内容：small 丢了 22 s 的语音。
- **英文需要提示词。** large-v3-turbo 对合成英文语音不加提示词时输出全小写、无标点；加一句英文提示词后正常。对真实英文视频（YouTube 样例）加提示词的输出带大小写和标点。
- 结论：
  - macOS 默认模型为 `whisper-large-v3-turbo-q5_0`。
  - VAD 默认关闭（`asr.vad = false`），已同步到 `docs/v0.md` D-07 和 §12。
  - 英文使用固定提示词，已同步到 `docs/v0.md` §8.2。
- 已知限制：中文输出的标点是半角，单个片段可长达约 28 s，引用只能定位到片段起点。
- 详细的命令行参数、进度行格式和 JSON 结构见 `third_party/whisper/NOTES.md`。

## S-07 工具链与真实下载

- 工具管理器真实安装了 ffmpeg、ffprobe、yt-dlp、deno、whisper-cli 和三个模型，冒烟测试全部通过。
- sha256 来自实际下载并与发布方的校验文件比对；模型的 sha256 取自 Hugging Face LFS 元数据，并由真实安装确认。
- 镜像（`huggingface.co` → `hf-mirror.com`）和本地导入（错误文件报 `CHECKSUM_MISMATCH`）实测通过。
- 真实链接导入（2026-10-09，直连网络，无代理、无 cookies）：
  - YouTube `https://youtu.be/jNQXAC9IVRw?list=…`：规范化后下载、转写、生成笔记成功，导出链接形如 `watch?v=jNQXAC9IVRw&t=0s`。
  - Bilibili `BV1GJ411x7h7`：下载到 1080p H.264 + AAC，全流程成功，导出链接形如 `?p=1&t=108`。
- 没有验证：代理、`tools update yt-dlp` 安装更新的版本（当时最新版就是锁定版）、`b23.tv` 短链。

## S-08 / S-09 取消、清理与单例

用 19 分 40 秒的音频，在转写阶段操作：

- 取消：`cancelling` 之后 0.1 s 任务变为 `cancelled`，`whisper-cli` 进程数为 0。
- 重试：沿用同一个 `job_id`，`attempt` 变为 2，已成功的阶段不重跑。
- `kill -9` Engine：`_guard` 在 1 s 内清理了 `whisper-cli`。
- 重新连接后 Engine 被自动拉起，任务从 `interrupted` 续跑到 `succeeded`。
- 在 `note_map` 完成 1/3 时 `kill -9` Engine：重启后记录了 `job.interrupted`、`job.resumed`，任务完成，`PRAGMA integrity_check` 返回 ok。
- 桌面构建和开发构建的 `build_id` 不同：空闲的旧 Engine 被新客户端自动替换；`engine status` 和 `engine stop` 可以直接操作版本不一致的 Engine。

## 端到端与四个入口

| 入口 | 做了什么 | 结果 |
| --- | --- | --- |
| CLI | 导入本地 MP4 并等待；读笔记、字幕；导出 md / vtt；重复导入；`--reprocess-from note` | 通过。重复导入返回 `already_processed`；重新生成笔记时前 5 个媒体阶段全部 `reused` |
| Web | 上传音频文件并导入；Chromium 中看资料库、笔记、点引用跳转 | 通过。当时用的是一次性登录码加 cookie；之后登录已移除，Web 界面改为可选开关（`web.enabled`），开关前后的访问规则另用 curl 验证过 |
| MCP | 用脚本经真实 stdio 走 JSON-RPC：发现 8 个工具、导入、轮询、读笔记和字幕、导出、错误结果 | 通过。Engine 由 MCP 进程在第一次调用时拉起 |
| 桌面 | 启动 `.app`，确认 WebView 与 Engine 通信 | 只做了启动检查，没有人工操作 |

失败与恢复：

- 在线模型返回 401：任务在 `note_map` 失败，错误码 `MODEL_AUTH_FAILED`，`retryable` 和 `user_action_required` 都为 true，下载和转写阶段保持成功。写入正确的 Key 后重试成功。
- 写入的 Key 没有出现在日志、导出、资料库和 `config.toml` 中；`secrets.toml` 权限为 0600。

## 验证中发现并修复的问题

- 两个视频音频完全相同时，后一个视频复用了前一个视频的字幕版本，导致片段 ID 属于别的视频。现在会为每个视频克隆出自己的字幕版本，不重新转写。
- `engine stop` 遇到版本不一致的 Engine 时自己也报 `ENGINE_VERSION_MISMATCH`，而提示正是让用户执行它。已修复。
- 事件总线的一个并发测试在不开竞态检测时必然超时（测试本身的问题）。已修复。
