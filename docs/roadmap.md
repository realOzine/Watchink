## 1. 产品目标

用 Go 实现一个本地优先、跨平台、极简部署的视频知识工具：将视频转为带来源引用的笔记，支持模糊搜索笔记与视频内容，包括视频画面；支持本地模型和在线模型；通过 Wails 提供桌面应用，同时提供 Web、CLI 和 MCP，让人和 AI / agent 使用同一套核心能力。

目标使用过程：

> 导入视频 → 处理音频与画面 → 生成可追溯笔记 → 搜索知识与视频证据 → 回到原视频核对 → 编辑、导出和继续使用。

版本划分：

| 版本 | 要解决的问题 | 发布结果 |
| --- | --- | --- |
| v0 | 能否方便地把视频变成可用笔记？ | 四个入口均可用，视频转笔记闭环，单文件分发与跨平台运行 |
| v1 | 能否从笔记和视频中找回需要的内容？ | 文字模糊搜索、语义搜索、画面搜索与时间定位 |
| v2 | 能否作为长期使用的完整知识工具？ | 完整模型配置与离线闭环、视觉检索增强、知识管理及产品可靠性 |

版本累积交付：v1 保留 v0 的全部能力，v2 保留 v0、v1 的全部能力。桌面、CLI、MCP、Web 从 v0 起就是正式入口，不能用空页面、占位命令或仅返回固定数据代替。

## 2. 全版本约束

### 2.1 部署与平台

**single-file deployment 的验收口径：每个目标平台提供一个可下载的发行文件，包含应用和前端；启动后允许解包工具、下载模型并创建数据目录。** Windows/Linux 优先单个可执行文件；macOS 使用单个发行文件交付 `.app`，应用包内部可包含多个文件。单个下载文件、单个进程、运行后只有一个文件是不同要求，本项目只承诺前者及无需手动拼装应用依赖。

- 最终用户不需要安装 Go、Node、Python、Docker 或独立数据库服务，不需要自行编译。
- FFmpeg、下载工具和推理引擎由程序准备或随包提供；模型首次按需下载，支持本地路径的阶段见各版本。
- 允许首次联网准备依赖；首次启动完全离线不是 v0 承诺。v2 提供预置工具与模型后的离线使用路径。
- 操作系统 WebView 和动态库前提必须列入发行说明。开发机已安装依赖不能作为“零依赖”的证据。
- 数据库、媒体、模型和配置放入独立数据目录；替换程序文件不能覆盖用户数据。
- 同一发行物提供桌面、服务、CLI、MCP 运行方式。无窗口模式不得要求用户先打开桌面窗口；系统库前提仍需单独说明。
- 桌面构建依赖 cgo 和系统 WebView，必须在各平台原生环境构建。可另外发布纯 Go（`CGO_ENABLED=0`）的无界面构建，供没有 WebKitGTK 的 Linux 服务器等环境使用；它是补充产物，不替代上述发行物，也不作为发布门槛。
- Windows 的 GUI 子系统会影响 CLI 与 stdio 的行为：若单个 exe 无法同时满足“双击无控制台窗口”和“CLI/MCP 正常输出”，允许发行 zip 内含 GUI 与控制台两个同源可执行文件，并在发行说明中写明（决策过程见 `docs/v0.md` S-02）。

初始发布验证矩阵建议固定为 macOS/arm64、Windows/amd64、Ubuntu Linux/amd64；每次发布记录确切 OS 版本及依赖。其他发行版、架构和 GPU 后端只有实测后才列为支持，不能从 Go 交叉编译成功推导。

Wails 使用系统 WebView，平台依赖应区分构建环境与用户运行环境。当前官方说明列出了 WebView2 及 Linux GTK/WebKit 相关依赖；因此必须先验证打包方案，不能笼统承诺所有操作系统零系统依赖。[Wails 安装说明](https://wails.io/docs/gettingstarted/installation/)、[构建说明](https://wails.io/docs/gettingstarted/building/)

### 2.2 架构边界

```text
Wails 桌面 / Web / CLI / MCP（均为客户端）
             ↓  本机 HTTP + 访问凭据
   Engine 进程（每个数据目录唯一）：同一套 Go 应用服务
             ↓
任务管理 / 媒体处理 / 模型适配 / 笔记与证据 / 检索
             ↓
       SQLite + 本地文件            外部工具与推理进程（子进程）
```

- 使用模块化单体，避免四个入口各自实现业务逻辑。
- Wails bindings 与 HTTP 是前端传输适配层；独立浏览器访问必须有真实 HTTP 服务，不能依赖 Wails 专用 bindings。v0 起桌面与 Web 共用同一套 HTTP 接口，Wails bindings 只用于文件对话框等原生能力。
- 同一数据目录只有一个任务调度所有者。桌面与多个 agent 同时接入时，共享任务和结果，不重复启动处理任务。v0 的实现方式是独立的 Engine 后台进程：它独占数据库写入与调度，由任一客户端按需拉起，空闲后退出；任何客户端退出都不会中断任务。
- SQLite 与数据目录中的文件产物是事实来源；Markdown 笔记是渲染与导出结果。直接修改数据目录中的文件不属于支持的用法，外部工具通过导出使用笔记。
- stdio MCP 可以桥接到应用服务；MCP 断开不默认取消已提交的后台任务。
- 默认仅本机访问，不引入用户账号、团队权限、云端托管、跨设备同步或移动端。这些不属于 v2 的隐含范围。
- Go 主程序管理独立媒体工具与推理进程；“Go 实现”不要求用 Go 重写解码器或模型推理引擎。

建议技术基线：Wails + React/TypeScript（Vite）；Go 应用服务；SQLite（纯 Go 驱动 `modernc.org/sqlite`，桌面与无界面构建共用）；yt-dlp（YouTube 需外部 JS 运行时，默认 Deno）；FFmpeg/ffprobe；whisper.cpp（自行构建并随程序内嵌）；按能力拆分的在线 API 与本地运行时适配，在线文本模型先接 OpenAI 兼容协议；官方 MCP Go SDK。检索从 v1 引入 FTS5 与嵌入式向量索引。具体版本在实现时锁定，不使用随运行漂移的 `latest`。不引入 LLM 编排框架、ORM 或 Web 框架。

Wails 版本：当前官方将 v2 标为稳定版本、v3 标为 beta。v0 设计选择 v2（理由见 `docs/v0.md` D-03），并须在 P0 技术验证中确认三平台结果；Wails 代码隔离在桌面外壳内。v1 开始前复评 v3，若 v2 版本需要多窗口或托盘，按届时 v3 的状态决定是否迁移。[官方版本说明](https://v3.wails.io/blog/wails-v3-beta/)

### 2.3 数据与 agent 契约

- 视频、字幕片段、笔记及任务从 v0 起使用稳定 ID；从 v1 起增加画面、检索片段及向量版本。
- 时间统一使用相对原视频的毫秒数；画面采用实际媒体时间戳。音频切分、重采样后必须映射回原时间轴。
- 模型引用真实片段 ID，由程序校验并生成时间链接。模型不能自由编造时间戳。
- 保存处理参数、模型标识和版本、输入指纹及产物关系，以便重试和重新处理。
- CLI 提供结构化 JSON 输出与稳定退出码；MCP 提供结构化结果、明确参数、错误码与可重试标识。机器输出不混入进度日志。
- 提交长任务返回 `job_id`，通过查询状态获取进度与产物；四个入口不必保持一个长连接等到视频处理完成。
- 来源文本和模型输出是数据，不能改变应用权限或执行任意命令。网络接口默认本机绑定，校验访问凭据或来源；本地路径按授权范围访问。

### 2.4 模型与运行时演进

| 能力 | v0 | v1 | v2 |
| --- | --- | --- | --- |
| ASR | 本地 whisper.cpp（随程序内嵌，模型按需下载；macOS 使用 Metal，其余 CPU） | 同 v0 | 本地与在线各至少一个；本地 GPU 后端按实测列入支持 |
| 文本生成（笔记） | 在线，OpenAI 兼容协议；本地 OpenAI 兼容端点（如 Ollama）可配置但不验收 | 同 v0 | 本地与在线各至少一个，纳入离线闭环 |
| 文本 embedding | — | 至少一个后端，可默认在线并标明外发数据 | 本地与在线各至少一个 |
| 画面分析（OCR / 描述） | — | 至少一个后端，可默认在线并标明外发数据 | 本地与在线各至少一个 |
| 多模态 embedding | — | — | 本地与在线各至少一个 |
| 运行时管理 | 工具与模型下载、sha256 校验、镜像与代理、本地导入 | 增加 embedding / 视觉模型 | 托管本地推理进程（如 llama.cpp server）的下载、启动、健康检查、版本与资源管理 |

本地推理始终以独立进程运行（随包或按需下载），主程序不通过 cgo 链接推理库。

### 2.5 接口演进

| 入口 | v0 | v1 | v2 |
| --- | --- | --- | --- |
| MCP 传输 | stdio（桥接 Engine） | 增加本机 Streamable HTTP（访问凭据 + Origin 校验） | 读写权限配置（如只读模式） |
| MCP 工具 | 导入、任务查询/取消/重试、列出视频、读取笔记与字幕、导出 | 增加搜索、证据读取、画面读取（含图片） | 增加问答、生成/回退笔记版本、能力查询 |
| CLI | 与 MCP 业务操作对等，JSON 输出与稳定退出码 | 增加搜索与证据读取 | 增加问答、版本、备份/迁移、模型管理 |
| HTTP API | `/api/v1`，供桌面、Web、CLI、MCP 共用 | 增量扩展，不破坏 v0 契约 | 同左；破坏性变更需提升主版本 |
| 桌面 | 单窗口，原生文件对话框，Agent 接入信息 | 搜索结果与画面浏览 | 后台运行与托盘、完成通知、一键写入常见 agent 客户端配置 |

接口契约（ID 格式、错误码、CLI 退出码、`lt://` 引用链接）一经 v0 发布即保持兼容；具体定义见 `docs/v0.md` 第 6.3、7.7、9、13 节。

## 3. v0：四入口与基本视频转笔记

### 3.1 范围

v0 的唯一业务主线是视频转笔记。检索、画面理解、知识问答和高级编辑不进入本版本；任务可靠性、来源引用和发行验证是主线完成的必要条件。

| ID | 需求 | 完成定义 |
| --- | --- | --- |
| V0-R01 | 导入视频 | 支持本地视频文件，以及无需用户登录即可访问的 YouTube、Bilibili 单视频链接；失败返回明确原因 |
| V0-R02 | 媒体处理 | 获取媒体、探测时长、提取音频；不依赖视频平台已有字幕才能继续 |
| V0-R03 | 语音转录 | 至少接入一个本地 ASR 后端，生成带起止时间的原语言字幕；覆盖中文、英文课程 |
| V0-R04 | 生成笔记 | 至少接入一个在线文本模型，将字幕整理成中文 Markdown 笔记，包含主题、主要知识点和证据引用 |
| V0-R05 | 长视频处理 | 按段处理并汇总，保留来源关系；不能静默截断超出模型上下文的部分 |
| V0-R06 | 查看与导出 | 列出视频及笔记、读取全文、查看字幕、跳转引用、导出 Markdown 与字幕文件 |
| V0-R07 | 任务管理 | 查看阶段和状态、取消、重试失败步骤；重启后识别中断任务，复用已完成产物 |
| V0-R08 | 基础配置 | 配置在线模型地址、模型名、凭据和数据目录；自动准备本地 ASR 工具及选定模型 |
| V0-R09 | 四入口 | 桌面、Web、CLI、MCP 均能导入、查询任务、读取与导出笔记，使用同一批数据 |
| V0-R10 | 发布 | 按第 2.1 节完成单文件分发与三平台基础运行验证 |

模型范围明确为“本地 ASR + 在线笔记生成”的最小混合路径。v0 不承诺完全本地生成笔记；文本生成、视觉分析等能力的完整本地/在线选择在 v2 验收。在线模型凭据由用户配置，任务不得因缺少凭据一直停留在运行状态。

### 3.2 四入口交付要求

| 入口 | v0 必须可完成的操作 | 特有要求 |
| --- | --- | --- |
| Wails 桌面 | 选择本地文件或粘贴链接 → 查看处理 → 读笔记 → 定位来源 → 导出 | 可直接启动窗口，提供基本模型配置与错误展示 |
| Web | 上传本地视频或提交链接 → 查看处理 → 读笔记 → 定位来源 → 导出 | 普通浏览器可使用；前端随应用交付，无需前端开发服务器 |
| CLI | 导入 → 取得任务 ID → 查询/取消/重试 → 读取/导出 | 支持 JSON，成功与失败退出码可区分，无需 GUI 会话 |
| MCP | 工具发现 → 导入 → 查询任务 → 获取笔记/字幕 → 导出 | 至少可被一个真实 MCP 客户端调用；不能要求 agent 模拟点击 UI |

命令和 tool 名称在实现前固定；至少覆盖 `import_video`、`get_job`、`cancel_job`、`retry_job`、`list_videos`、`get_note`、`get_transcript`、`export_note` 对应的业务操作。CLI/MCP 的时间定位以媒体标识和时间值表达，不要求它们自己渲染播放器。v0 的 CLI 命令与退出码、MCP tools、HTTP 接口已在 `docs/v0.md` 第 13 节定义，错误码见其第 7.7 节，P0 结束前冻结。

### 3.3 端到端闭环

```text
下载发行文件并启动
  → 完成必要工具准备，配置在线模型
  → 从任一入口导入视频
  → 下载/读取 → 提取音频 → 本地转录 → 在线生成笔记
  → 保存字幕、笔记和引用
  → 从另一个入口读取相同结果
  → 跳转原视频核对 → 导出 Markdown
```

失败闭环：断网、无效凭据或主动中断 → 标记失败阶段及原因 → 修复条件 → 重试该阶段 → 复用先前产物 → 完成笔记。取消后不再提交后续步骤，已完成产物按记录保留。

### 3.4 发布验收

| ID | 验收场景 | 通过规则 |
| --- | --- | --- |
| V0-A01 | 干净环境启动 | 三个目标平台分别从发行文件启动；不安装开发语言、Docker 或独立数据库；记录系统前提、工具准备步骤及实际文件体积 |
| V0-A02 | 三种输入 | 本地文件、YouTube、Bilibili 各完成一个真实视频；链接记录测试日期。受平台限制失败要正确报告，但不能以失败提示代替该平台成功样例 |
| V0-A03 | 基础质量 | 固定一段中文、一段英文课程，每段 5–15 分钟；预先标注各 10 个核心知识点，中文笔记各覆盖至少 8 个，且不出现与原视频相反的核心结论 |
| V0-A04 | 引用可追溯 | 所有引用 ID 均可解析，时间在视频范围内；抽查 10 处，至少 8 处能在引用区间及前后 5 秒内找到支持证据 |
| V0-A05 | 长视频 | 至少一个 60 分钟以上样例完成处理；在前、中、后段各预标注 3 个知识点，各段至少覆盖 2 个，保留全部转录产物，无静默截断 |
| V0-A06 | 四入口真实闭环 | 每个入口至少独立提交并完成一次任务；另一个入口可通过相同 ID 读取其结果；Web 在独立浏览器运行，MCP 使用真实客户端 |
| V0-A07 | 失败与恢复 | 模拟下载失败、模型鉴权失败、生成中断；错误阶段准确。修复后重试完成，已成功的下载/转录不重复执行，不产生重复有效产物 |
| V0-A08 | 取消与重启 | 处理中取消后，受管理的工作进程在 10 秒内停止或有明确超时处理；重启可识别中断任务并继续，不永久停在 `running` |
| V0-A09 | 单一调度所有者 | 桌面与两个客户端同时连接同一数据目录，无重复调度、数据库损坏或相互覆盖；重复请求有可说明的去重/重复处理策略 |
| V0-A10 | 导出与保留 | Markdown、字幕可在其他工具打开；重启及替换程序后仍可读取原数据；日志与导出文件不泄露模型凭据 |

v0 的资源使用和处理时长必须记录，不提前宣称实时转录或固定速度。不同模型输出不要求逐字一致，验收关注内容、引用和功能。

### 3.5 实现路径

1. **P0 技术验证**：先验证三平台打包、Wails 窗口、同发行物的无窗口模式、视频播放/跳转，以及工具启动与取消。这些风险未验证前不铺开完整 UI。
2. **P1 纵向切片**：建立最小数据模型和 SQLite 持久化任务，实现“本地文件 → 转录 → 笔记 → 导出”的一条纵向路径。
3. **P2 主线与可靠性**：增加链接下载、分段处理、引用校验、重试与恢复。
4. **P3 四入口**：接通四入口并验证共用数据和调度；补齐新用户启动配置。
5. **P4 发布**：执行 V0-A01～V0-A10，保存证据后发布 v0。

各阶段的交付内容、退出标准，以及 P0 的 11 个技术验证项（S-01～S-11）及其回退方案，见 `docs/v0.md` 第 18 节。

## 4. v1：笔记与视频搜索

### 4.1 范围

v1 新增搜索能力，结果必须回到真实笔记或视频证据。搜索字幕只是视频搜索的一部分；必须覆盖没有口述对应内容的画面。

| ID | 需求 | 完成定义 |
| --- | --- | --- |
| V1-R01 | 文字模糊搜索 | 搜索笔记、标题、字幕及画面识别文字；覆盖关键词、中文短词、部分匹配和有限拼写容错 |
| V1-R02 | 语义与跨语言检索 | 支持用自然语言描述意思，并用中文查找英文课程内容 |
| V1-R03 | 画面提取 | 采样、画面变化检测和去重，保留实际时间戳及代表图；采样策略可配置 |
| V1-R04 | 基础画面搜索 | OCR 和/或视觉模型提取文字及内容描述，建立画面索引；不能只把字幕命中附上一张截图 |
| V1-R05 | 结果展示 | 返回对象类型、摘要、引用、视频时间和可用截图；支持按视频及对象类型过滤，聚合相邻重复命中 |
| V1-R06 | 定位与核对 | 桌面/Web 点击结果可打开笔记段落或跳到视频时刻；CLI/MCP 返回等价的结构化证据 |
| V1-R07 | 索引生命周期 | 新增或重新生成内容后更新索引；删除的内容不再出现；旧 v0 数据可补建索引 |
| V1-R08 | 四入口搜索 | 所有入口均可搜索、筛选和按需读取完整证据；MCP 可读取实际截图；MCP 增加本机 Streamable HTTP 传输（访问凭据与 Origin 校验） |

文字检索与向量检索分别召回后融合排序。中文短查询、代码标识符、错别字和语义查询分别测试，不以“接上向量数据库”替代完整搜索能力。

技术候选（在 `docs/v1.md` 中确定）：SQLite FTS5 `trigram` 分词做子串匹配，少于 3 个字符的查询降级为前缀或 `LIKE` 匹配；可选拼音与首字母索引；多路结果用 RRF（Reciprocal Rank Fusion）融合；向量先以 int8 量化后在内存中暴力检索，索引接口抽象，规模增长后替换为 HNSW 等近似索引；向量表以模型标识区分，换模型时增量重建。画面提取用 FFmpeg 场景检测加固定间隔兜底，用感知哈希去重，并设帧数上限控制分析成本。

v1 至少固定一个文本 embedding 和一个画面分析后端。默认可使用在线能力降低集成复杂度，必须标明哪些数据会发送出去；跨能力的本地替代与离线验收在 v2 完成。基础画面搜索通过视觉文字化实现；直接多模态向量检索放在 v2。

### 4.2 端到端闭环

```text
导入/选择已有视频
  → 字幕与笔记分块 + 画面提取与分析
  → 建立文字索引与向量索引
  → 输入关键词、模糊描述或画面描述
  → 多路召回与结果聚合
  → 读取笔记/截图/附近字幕
  → 跳转原视频验证 → 继续阅读或导出
```

Agent 闭环：`search` → 根据结果 ID 调用 `get_evidence` / `get_frame` → 读取真实上下文 → 返回带引用的结果。Tool 名称是拟定契约，不能只返回无法继续获取内容的摘要。

### 4.3 发布验收

先冻结至少 10 个视频的评测集，包含中文、英文、PPT、代码演示和无对应口述的视觉内容。冻结 40 条正向查询：文字模糊查询、中文查英文语义查询、画面文字查询、非文字画面描述查询各 10 条；另设 10 条无相关内容查询。每条正向查询人工标注相关笔记/画面 ID 及视频时间区间，不能用待测模型自身输出充当答案。

| ID | 验收场景 | 通过规则 |
| --- | --- | --- |
| V1-A01 | 搜索命中 | 40 条正向查询中，至少 32 条 Top-5 包含人工标注的相关结果；每类至少 7/10，防止只优化文字查询 |
| V1-A02 | 画面独立贡献 | 画面类查询中至少 5 条答案不在字幕/笔记正文中；至少 4 条 Top-5 命中真实画面，展示截图及时间 |
| V1-A03 | 时间定位 | 对命中的视频结果，至少 80% 的首选定位点落在人工标注区间或边界前后 5 秒内；单帧时间不能冒充已确认的整个事件区间 |
| V1-A04 | 短词与容错 | 查询集中包含两字中文词、英文标识符和常见拼写错误；分别记录命中，不因分词限制全部返回空结果 |
| V1-A05 | 无关查询 | 10 条无关查询至少 8 条按冻结的阈值/策略返回无高相关结果或明确低相关状态；不生成虚构的笔记、画面或时间位置 |
| V1-A06 | 旧数据与更新 | v0 数据补建索引后可搜索；重新生成、删除并完成索引任务后，旧结果不残留；模型更换后不混用不兼容向量 |
| V1-A07 | 四入口一致性 | 同一索引版本与查询参数返回一致的结果 ID 和可用证据；MCP 客户端可继续读取图片，不要求访问应用内部路径；MCP 的 stdio 与 Streamable HTTP 两种传输返回一致结果，HTTP 传输拒绝无凭据或非法 Origin 的请求 |
| V1-A08 | 响应与资源 | 在记录的基准机器、至少 10,000 个检索对象上，执行固定 100 条查询，预热后本地召回与融合 P95 ≤ 2 秒；单独报告在线编码/重排及端到端耗时，不隐藏网络成本 |
| V1-A09 | 降级与修复 | 中断索引任务后可重建；缺少 embedding 或画面后端时明确标注能力缺失，已有文字检索仍可使用，不将未索引状态误报为“无相关内容” |

Top-5 命中率定义为“前五个结果中至少有一个人工标注相关对象的查询数 / 正向查询总数”。性能数字是发布目标，必须附硬件、模型、索引规模及测量范围，不能当作所有机器的承诺。

### 4.4 实现路径

0. 编写 `docs/v1.md`（检索对象、索引结构、接口增量与取舍），复评 Wails v3。
1. 定义检索对象、证据读取接口及评测集，先测关键词/子串检索基线。
2. 增加多语言 embedding、语义召回与融合，记录相对基线的质量变化。
3. 接入画面抽取、视觉分析和独立画面索引，完成无对应口述的画面样例。
4. 接通四入口的结果展示、过滤、证据读取与时间跳转。
5. 完成旧数据补索引、失效处理和性能验证，执行 V1-A01～V1-A09 后发布。

## 5. v2：完整产品

### 5.1 完整产品的范围

v2 的“完整”指下表列出的能力全部可用，并通过长期数据与离线使用验收；不代表无限增加功能。检索问答、组织和编辑是本次规划提出的产品补齐项，后续可在开始实现前调整。

| ID | 需求 | 完成定义 |
| --- | --- | --- |
| V2-R01 | 完整本地/在线模型配置 | 按 ASR、文本生成、视觉分析、文本 embedding、多模态 embedding 配置后端；每项至少一个本地与一个在线可用实现，组合有明确支持矩阵 |
| V2-R02 | 全本地闭环 | 工具和模型准备后，断网完成本地视频导入、转录、笔记生成、画面处理、搜索和导出，不要求用户另外搭建服务 |
| V2-R03 | 直接多模态检索 | 通过兼容的文本/图像向量空间检索画面；候选附近可加密采样和分析，补足仅靠 OCR/描述的遗漏 |
| V2-R04 | 可编辑知识库 | 编辑 Markdown、保留生成/人工修改版本、标签与收藏、删除与重新处理；更新同步到搜索索引 |
| V2-R05 | 基于证据的问答 | 在选定视频或整个库内提问，答案关联可读取的原始证据；证据不足时说明限制，不编造来源 |
| V2-R06 | 模型与运行时管理 | 查看能力与资源需求、下载进度、校验和、版本；支持本地导入、损坏恢复、可控更新及兼容性检查；托管本地推理进程（如 llama.cpp server）的下载、启动、健康检查与停止，用户无需另行搭建服务 |
| V2-R07 | 完整任务体验 | 批量导入、队列、并发/资源限制、取消与恢复；区分关闭窗口、后台处理与退出应用；桌面提供后台运行入口（如托盘）与完成通知 |
| V2-R08 | 数据维护 | 可备份恢复数据库及关联文件，迁移数据目录，查看存储占用，清理可重建缓存；程序升级保留数据 |
| V2-R09 | 完整 agent 工作流 | 四入口覆盖新增核心业务；agent 可搜索、取证、问答、生成新版本并导出，写入与删除有明确权限边界；桌面可一键写入常见 agent 客户端的 MCP 配置 |
| V2-R10 | 产品发行 | 三平台发行与升级回归、依赖清单、用户启动说明、能力诊断和已知限制；系统安全机制下可说明安装与启动路径 |

本地/在线后端可以共用服务或供应商，不要求为每项能力引入独立框架。可选 reranker 不构成新的强制双后端要求；如果启用，必须标明它是否影响完全离线运行。

本地资源不足时显示原因并允许选择更小模型或明确切换在线配置；禁止静默上传。离线闭环使用本地视频，不能把联网下载 YouTube/Bilibili 计入离线承诺。

### 5.2 端到端闭环

人使用的闭环：

```text
启动桌面/浏览器 → 选择本地或在线能力配置 → 批量导入
  → 自动处理 → 编辑和组织笔记 → 搜索/问答
  → 阅读原始证据并定位视频 → 导出
  → 备份 → 升级/迁移 → 恢复后继续使用
```

Agent 使用的闭环：

```text
读取可用能力 → 提交导入 → 查询任务
  → 搜索 → 获取字幕及画面证据
  → 生成带引用的新笔记版本 → 导出
  → 用户在桌面端查看同一产物与处理记录
```

离线闭环：预置发行包、工具与模型 → 断开网络 → 导入本地视频 → 完成转录、笔记、视觉处理及搜索 → 导出 → 重启后继续读取。

| ID | 验收场景 | 通过规则 |

## 6. 验收记录与发布规则

每个版本发布时形成一份实际验收记录，建议放在 `docs/acceptance/v0.md`、`v1.md`、`v2.md`。本次只定义路径，不预生成“已通过”的记录。

记录至少包含：

1. 应用版本/提交、发行文件及校验和、测试日期。
2. OS、CPU、内存、GPU、系统库与工具/模型版本。
3. 固定样例清单、来源和内容标识；链接可访问性单独记录，质量回归优先使用稳定本地样例。
4. 每个验收 ID 的状态：通过、失败、未执行；附命令、日志、截图或产物位置。
5. 笔记/检索/问答的人工标注与逐条结果，不只报一个总分。
6. 性能的测试范围、预热条件、端到端耗时、峰值内存和失败率。
7. 已知限制、未支持的平台/模型组合，以及数据迁移方法。

发布门槛：该版本所有必须项通过，继承版本的核心路径无回归。没有目标平台运行证据时，只能标记该平台未验证；不能把编译、mock、单元测试或演示视频视为真实端到端验收。若范围变化，先更新本 roadmap，再按更新后的规则实施和验证。

技术验证（P0 等）的记录放在 `docs/spikes/`，格式与验收记录相同：每项写明通过标准、实测结果、环境与证据位置；未通过时记录采用的回退方案，并同步更新对应版本的设计规格。

## 7. 跨版本风险

| 风险 | 涉及版本 | 应对 |
| --- | --- | --- |
| YouTube / Bilibili 风控、提取器失效、JS 运行时要求变化 | 全部 | 工具版本可单独更新并校验；错误码区分来源不可用与被拦截；验收记录日期与网络环境；质量回归优先使用本地样例 |
| 系统 WebView 差异（跨源访问、媒体解码、Linux 发行版依赖） | 全部 | 前端以 HTTP 为唯一业务通道；仅承诺实测平台；发行说明列出系统前提 |
| 未签名应用被 Gatekeeper / SmartScreen 拦截，杀毒软件误报 | 全部 | 尽早确定代码签名；不能签名时在发行说明中给出启动步骤 |
| CPU 推理速度与资源占用 | v0 起 | 记录实测数据，不承诺速度；按平台选择默认模型；v2 引入 GPU 后端与资源限制 |
| 在线模型协议与结构化输出能力差异 | v0 起 | 统一协议适配与降级路径；契约样例测试；输出一律经程序校验 |
| Wails v2 维护节奏与 v3 迁移 | v1、v2 | Wails 代码隔离在桌面外壳；按版本节点复评 |
| 在中国大陆访问 GitHub / Hugging Face 不稳定 | 全部 | 下载镜像与代理配置，sha256 校验不变；支持本地导入工具与模型 |
| 第三方工具与模型的许可（FFmpeg GPL 构建、模型权重） | 全部 | 运行时从上游下载而非再分发；如改为随包或镜像分发，先完成许可合规评估 |
| 数据格式演进破坏旧数据 | v1、v2 | 迁移脚本随程序发布并自动备份；新版本数据库不允许被旧程序打开；每个版本回归旧数据样本 |

## 8. 候选池（未纳入版本承诺）

以下能力在讨论中出现过，目前不属于任何版本的范围。纳入某个版本时，先在本文增加需求与验收 ID。

- 复用平台已有字幕以加快处理（不能作为必需路径，见 V0-R02）。
- 说话人分离；多音轨选择。
- 播放列表与批量链接导入；需要登录态的视频（cookies）。
- 全局快捷键唤起的快速搜索窗口。
- 用户自定义笔记模板与提示词。
- 与 Obsidian 等笔记库的双向同步（v0–v2 只提供导出）。
- 字幕翻译与双语笔记。
- 通过动态加载（如 purego）在进程内调用推理库，替代独立推理进程。
- 系统钥匙串保存凭据。

当前进度：v0 设计规格已编写（`docs/v0.md`），待 P0 技术验证确认；v0、v1、v2 均未实现，本文不代表任何功能、跨平台发行或模型质量已验收。
